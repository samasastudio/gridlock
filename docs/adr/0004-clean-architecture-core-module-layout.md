# 0004: Clean Architecture Four-Layer Module Layout in `packages/core`

To prevent ticket-shaped monolith files that mix domain models, constants, transport adapters, and orchestration, `@samasastudio/gridlock-core` (`packages/core/src`) is organized into four top-level layer directories behind the public `src/index.ts` barrel and Composition Root: `controllers/` (inbound HTTP route handlers and request/response serialization), `use-cases/` (application business workflows plus pure deterministic functions under `use-cases/helpers/`), `adapters/` (outbound repository persistence, HTTP/Playwright loaders, and Cloud Logging implementations), and `interfaces/` (Zod schemas, TypeScript domain models, abstract port contracts, constants, and seed defaults). Runtime control flow runs `controllers/ -> use-cases/ -> adapters/`, while source-code dependencies point strictly inward via Dependency Inversion (`controllers/` -> `use-cases/` -> `use-cases/helpers/` -> `interfaces/`, and `adapters/` -> `interfaces/`), with default adapter instances wired at the Composition Root (`src/index.ts`) and enforced by `scripts/lint-checks.mjs` (`<= 300` lines per file, inward-only imports, and non-mutative `const`/array-method control flow).
