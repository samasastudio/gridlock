# 0002: Cloud Firestore and Cloud Storage as Single Persistence Spine

Gridlock uses Cloud Firestore (validated at runtime via shared Zod schemas) for all structured documents (`projects`, `observations`, `raw_captures`, `generated_illustrations`, `connector_configs`, `repair_changelog`, `run_records`, `efficiency_scorecard`) and Google Cloud Storage for immutable SHA-256 Raw Captures (`.gz`) and `.webp` Generated Illustrations. Canonical records, Efficiency Scorecard rollups, Repair Changelog entries, per-run `run_records` time-series (`~156 KB/year`), and milestone-referenced `raw_captures` are retained indefinitely, while unreferenced Raw Captures and ephemeral Scenario Branches auto-purge after 90 days via native Firestore TTL and Cloud Storage Object Lifecycle rules. We rejected syncing a SQLite database file (`gridlock.db`) over object storage and rejected managed PostgreSQL (Cloud SQL) because scraped regulatory filings naturally arrive as semi-structured nested documents, and Firestore + Cloud Storage operate within Google Cloud's $0/month Always-Free tier without custom file-locking or pre/post-run database blob synchronization.
