# 0002: Cloud Firestore and Cloud Storage as Single Persistence Spine

Gridlock uses Cloud Firestore (validated at runtime via shared Zod schemas) for all structured documents (`projects`, `observations`, `source_artifacts`, `visual_plates`, `connector_configs`, `repair_changelog`, `telemetry_runs`, `telemetry_summary`) and Google Cloud Storage for immutable SHA-256 raw filings (`.gz`) and `.webp` Visual Plates. Canonical records, efficiency rollups, repair logs, per-run `telemetry_runs` time-series (`~156 KB/year`), and milestone-referenced `source_artifacts` are retained indefinitely, while unreferenced raw artifacts and ephemeral branches auto-purge after 90 days via native Firestore TTL and Cloud Storage Object Lifecycle rules. We rejected syncing a SQLite database file (`gridlock.db`) over object storage and rejected managed PostgreSQL (Cloud SQL) because scraped regulatory filings naturally arrive as semi-structured nested documents, and Firestore + Cloud Storage operate within Google Cloud's $0/month Always-Free tier without custom file-locking or pre/post-run database blob synchronization.
